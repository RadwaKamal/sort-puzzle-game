# Sort Puzzle Game — Project Brief

Oct 6, 2026 · @dodo

## Overview

Build a casual sort puzzle game for Android first, written once as a web game so it can later ship to iOS and the web. The player pours colored items between containers until each container holds one color.

Goals:

- **Near-zero running cost:** fully offline, no backend, no accounts, no servers.
- **Light development:** one core mechanic, levels generated by code, no hand-made level content.
- **Attractive through polish:** flat shapes, a tight color palette, and strong feedback (animation, particles, sound) instead of complex art.
- **Monetized with ads:** rewarded ads for helpers (undo, extra container, skip), an occasional interstitial, and a one-time "Remove ads" purchase later.

Working theme: **potions** (glass flasks, liquid layers). The theme lives in one config so it can change later.

## Tech stack

Web game wrapped as a native app with Capacitor, chosen over Tauri 2 because Capacitor has a mature AdMob plugin and the game needs no native backend.

| Layer | Choice | Why |
| --- | --- | --- |
| Language | TypeScript | Type safety with little overhead |
| Game engine | Phaser 3 | Mature 2D engine, tweens, particles, input, sound built in |
| Build tool | Vite | Fast dev server, simple config |
| Native wrapper | Capacitor | Android now, iOS later, same codebase |
| Ads | `@capacitor-community/admob` | Rewarded, interstitial and banner ads |
| Storage | Capacitor Preferences (localStorage on web) | Saves progress offline |
| Tests | Vitest | Unit tests for level generation and game rules |

Use the latest stable versions at the time of setup. Ads must be behind an interface so the web build runs with a no-op mock.

## Game rules

The player taps a source flask, then a target flask, and the top color layer pours across if the move is legal. The level is won when every flask is empty or full of a single color.

**Core rules**

- Each flask holds 4 layers.
- A pour is legal if the target is empty, or its top color matches and it has space.
- A pour moves as many matching top layers as fit.
- A level has N colors in N + 2 flasks (two start empty).

**Level generation**

- Generate levels from a seed so level 37 is always the same level.
- Build by shuffling a solved state, then verify solvability with a solver (BFS/DFS with state hashing). Reject and regenerate unsolvable or trivially easy layouts.
- Difficulty ramps with level number: more colors, fewer free flasks, more mixing. Start at 3 colors, cap around 12.

**Helpers (monetization hooks)**

- **Undo:** 3 free per level, more via rewarded ad.
- **Extra flask:** adds one empty flask, via rewarded ad.
- **Restart:** always free.
- **Skip level:** via rewarded ad.

**Progression**

- Linear level list with a level-select screen.
- Save current level and unlocked level locally.
- Show an interstitial at most every 3 completed levels, never during the first 5 levels.

## Visual and feel

The game should look clean and feel satisfying, using code-drawn shapes rather than drawn art.

- **Shapes:** flasks and liquid drawn with Phaser Graphics (rounded rectangles, gradients, soft shadows). No sprite art required for v1.
- **Palette:** one dark background and up to 12 liquid colors that stay distinct for color-blind players. Add an optional symbol per color for accessibility.
- **Theme config:** all colors, fonts and sizes in one `theme.ts` file.
- **Layout:** portrait only, scales from small phones to tablets, respects safe areas (notches).
- **Font:** one rounded Google Font (for example Fredoka or Nunito), bundled locally.

**Juice (feedback on every action)**

- Selected flask lifts and tilts slightly.
- Pour animates as the flask tilts over the target and liquid flows across.
- Squash-and-stretch on landing; a small bounce when a flask completes.
- Particle burst and sparkle when a flask fills with one color; a bigger celebration on level win.
- Gentle shake on an illegal move.
- Short sounds for select, pour, complete, win and error (free packs from Kenney.nl or Freesound, license noted in `CREDITS.md`).
- Light haptic tap on Android via Capacitor Haptics.
- Sound and haptics toggles in settings.

## Repo structure

Keep game logic as pure TypeScript, separate from Phaser rendering, so rules and level generation can be unit-tested.

```text
/
├─ src/
│  ├─ main.ts            # Phaser game config and boot
│  ├─ theme.ts           # colors, fonts, sizes
│  ├─ core/              # pure logic, no Phaser imports
│  │  ├─ board.ts        # state, legal moves, pour, win check
│  │  ├─ generator.ts    # seeded level generation
│  │  ├─ solver.ts       # solvability check
│  │  └─ rng.ts          # seeded random
│  ├─ scenes/            # Boot, Menu, LevelSelect, Game, Settings
│  ├─ view/              # Flask drawing, pour animation, particles
│  ├─ services/
│  │  ├─ ads.ts          # AdService interface + AdMob and mock implementations
│  │  ├─ storage.ts      # save/load progress
│  │  └─ audio.ts        # sound and haptics
├─ public/assets/        # sounds, font
├─ tests/                # Vitest tests for core/
├─ android/              # generated by Capacitor
├─ capacitor.config.ts
├─ CREDITS.md
└─ README.md             # setup, run, build-APK steps
```

## Milestones

Work through these in order, finishing each with a playable build before starting the next.

1. **Scaffold:** Vite + TypeScript + Phaser project, ESLint/Prettier, Vitest, README with run instructions. A blank game scene runs in the browser.
2. **Core logic:** `board.ts`, `rng.ts`, `generator.ts`, `solver.ts` with unit tests. Every generated level for levels 1–200 is proven solvable.
3. **Playable game:** draw flasks, tap-to-select, pour, win detection, next level, restart, undo. Playable in a mobile browser.
4. **Juice and audio:** pour animation, particles, squash-and-stretch, shake, sounds, haptics, settings toggles.
5. **Menus and progress:** main menu, level select, settings, saved progress.
6. **Android build:** add Capacitor and the Android platform, app icon and splash, document how to build a debug APK and a release AAB.
7. **Ads:** `AdService` with AdMob (Google test ad IDs only) and a web mock. Wire rewarded helpers and the interstitial rule.
8. **Release prep:** privacy policy page (static, can host free on GitHub Pages), store listing text, screenshots checklist, and a web build for itch.io.

Before milestone 8, check Google Play's current requirements for new personal developer accounts (closed testing with testers, target API level).

## Constraints and non-goals

Anything that adds a running cost or a server is out of scope for v1.

**Constraints**

- No backend, no login, no analytics server. The app must work fully offline (ads simply don't show offline).
- Only free, commercially licensed assets; record each in `CREDITS.md`.
- Use AdMob test IDs in all development builds; real IDs come from config, never hard-coded.
- Keep the APK small (target under 15 MB) and run at 60 fps on a mid-range Android phone.
- The developer is new to game development: keep code simple, commented where non-obvious, and explain setup steps in the README.

**Not in v1**

- iOS build (planned later, same codebase).
- Online leaderboards, multiplayer, cloud saves.
- In-app purchases (the "Remove ads" purchase comes after launch).
- Hand-designed levels, level editor, daily challenges.
